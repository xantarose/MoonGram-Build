# MoonGram

Неофициальный клиент Telegram для iOS с локальным оформлением. Проект находится в разработке: готовой проверенной на iPhone IPA пока нет. Полная основа Telegram с первыми патчами MoonGram уже скомпилировалась и слинковалась на macOS; её проверка упаковки выявила неверное имя основного приложения, исправленное следующим патчем.

## Что находится в репозитории

- `MoonGram/Core` — отдельное хранилище косметических профилей, пресеты, три режима отображения, точные суммы, проверка импорта.
- `MoonGram/UI` — нативные редакторы профиля, балансов, подарков, моделей, фонов и узоров; импорт изображений и JSON; настройки обмена и экспериментального хранилища.
- `MoonGram/NativeGifts` — подключение каталога реальных моделей, фонов и узоров через Telegram Engine и штатного анимированного `GiftItemComponent` к редактору и коллекции MoonGram. Код требует проверки полной сборкой и в авторизованном клиенте; отдельное QA-приложение этот адаптер не собирает.
- `MoonGram/Vault` — локальное AES-GCM хранилище экспериментальных копий, ключи в Keychain, ограничения размера. Восстановление из облака не предусмотрено; каталог помечается для исключения из backup.
- `MoonGram/Bridge` — ограниченные точки интеграции архива с полученными сообщениями и галереей Telegram.
- `service` — небольшой сервис оформления для приглашённых пользователей; в нём нет сообщений, ключей Telegram и данных кошелька.
- `patches/moongram.patch` — изменения официальной основы. Исходная база закреплена в `upstream.lock.json`.
- `tools` — подготовка исходников, проверки, отдельное iOS QA-приложение и сборочный маршрут для macOS.

## Оригинальные данные и визуалы

Оформление не меняет настоящий Premium, баланс, право на username/номер и владение подарками. Сетевой слой Telegram, его платежные сущности и настоящая подписка остаются источником реальных прав.

Режимы:

- **Оригинал** — наложения выключены; пресеты сохраняются.
- **Визуалы** — заменяются поддерживаемые поля интерфейса; недостающие данные берутся из настоящего профиля.
- **Оригинал + визуалы** — настоящие поля сохраняются, косметические данные показываются отдельно.

Коллекционные предметы MoonGram находятся в собственной коллекции, доступной из профиля. Настоящие подарки Telegram не удаляются и не переписываются. Встроенный кошелёк оформления — локальный экран MoonGram; произвольные сторонние Wallet Mini Apps не подменяются.

Для оформления из Telegram сохраняются идентификаторы типа подарка, модели, узора и фона. Полные media descriptors и session data не экспортируются; актуальные ресурсы читаются через Engine текущего аккаунта. При недоступности ресурсов показывается состояние загрузки/повторного запроса. Локальные предметы пока не подмешиваются в штатную вкладку настоящих подарков Telegram.

Переключение режима не удаляет пресеты. Удаление приложения и изменение комплекта подписи — отдельные операции: перед ними нужен экспорт оформления. Секретные ключи и содержимое экспериментального хранилища в такой экспорт не входят.

## Версия основы

На 18 ноября 2026 года официальный App Store распространяет Telegram **13.2.2**, выпущенный 16 ноября. Проверенные опубликованные исходники Telegram пока имеют тег **release-13.2**, commit `24638bc69bd083981b178dd1e7f921eebbf7fc46`. MoonGram основан на этих исходниках; исправления отсутствующего исходного релиза 13.2.2 не выдумываются. [App Store](https://apps.apple.com/us/app/telegram-messenger/id686449807), [исходная база](https://github.com/TelegramMessenger/Telegram-iOS/tree/24638bc69bd083981b178dd1e7f921eebbf7fc46).

## Локальная проверка

Нужны Swift и Node.js 24 или новее. Внешних npm-зависимостей нет.

```sh
swift test
node --test service/test/server.test.mjs
python3 tools/prepare.py
python3 tools/check.py
python3 -m unittest discover -s tools/tests
```

В ограниченной Linux-среде Swift Build не может создать необходимые IPC-сокеты. Для неё проверен запасной запуск `swift test --build-system native`; кэш компилятора должен находиться в доступном для записи каталоге.

`tools/prepare.py` применяет патч только к закреплённому commit и отказывается сбрасывать неизвестные изменения. Каталоги `submodules/MoonGram*` в подготовленном checkout генерируются заново: изменяйте исходники в `MoonGram/`, затем повторяйте подготовку.

## Сборка iOS

Для полной основы нужен Mac с **Xcode 27.1**, как задаёт `versions.json` Telegram. Первая проверка — отдельное приложение MoonGram QA, собирающее наши Core/Vault/SwiftUI-модули без Telegram-сессии:

```sh
python3 tools/ios_qa.py
```

Оно сохраняет скриншоты в `dist/ios-qa/`. Это проверка собственных экранов, а не полной интеграции Telegram, уведомлений или работы на физическом устройстве.

18 ноября 2026 года [первый запуск проверок на macOS](https://github.com/xantarose/MoonGram/actions/runs/44320879230) завершился успешно: 10 тестов Core, 5 тестов сервиса, применение патча и компиляция QA-приложения с Xcode 27.1. Получены и просмотрены четыре снимка настроек и предпросмотра в светлой и тёмной темах на симуляторе iPhone 17e с iOS 27.0. Проверка других размеров, увеличенного шрифта и полного клиента остаётся отдельной работой.

Для полного клиента скопируйте `config/build.example.json` в `build.local.json`, укажите свой Telegram `api_id`/`api_hash`, Apple Team ID и отдельный bundle ID.

Для simulator и unsigned-device вместо полного конфига можно подготовить его из отдельного локального JSON только с `api_id` и `api_hash`:

```sh
python3 tools/build_configuration.py --kind simulator --local-api .private/telegram.local.json
```

В этих двух режимах пустой `team_id` обозначает отсутствие подписи; выдуманная Apple identity не создаётся. Все поля валидируются перед генерацией Starlark-конфигурации.

```sh
python3 tools/build.py --configuration build.local.json --kind simulator
python3 tools/build.py --configuration build.local.json --kind unsigned-device
python3 tools/build_configuration.py --kind standalone-device --local-api .private/telegram.local.json
python3 tools/build.py --configuration build.local.json --kind standalone-device
python3 tools/build.py --configuration build.local.json --kind device --codesigning /path/to/codesigning
```

В каталоге подписи нужны `profiles/` и `certs/`, а в macOS — соответствующая signing identity. Пригодность сертификата и профилей проверяется сборкой; успешная установка не доказывает работу push.

В GitHub Actions подготовлены проверки и ручной workflow сборки. Конфигурация и сертификаты передаются **только через Actions Secrets**, не коммитятся даже в приватный репозиторий:

- `MOONGRAM_BUILD_CONFIG` — содержимое локального build JSON.
- Для simulator/unsigned-device достаточно `MOONGRAM_TELEGRAM_API` — JSON с полями `api_id` и `api_hash`; полный `MOONGRAM_BUILD_CONFIG` имеет приоритет.
- Для device: `MOONGRAM_CERTIFICATE_P12_BASE64`, `MOONGRAM_CERTIFICATE_PASSWORD`, `MOONGRAM_PROFILES_ZIP_BASE64`.

Runner `xcode-27` проверен для тестов и отдельного QA-приложения. Достаточность его ресурсов для полного Telegram и совместимость конкретного комплекта подписи пока не проверены. Simulator IPA нельзя устанавливать на iPhone.

`MoonGram-unsigned.ipa` — ARM64-сборка для последующей подписи, а не готовое подписанное приложение. Opt-in патч закреплённых rules_apple пропускает встраивание отсутствующего профиля только вместе с двумя явными флагами отключения подписи; обычный signed build сохраняет проверки. Основной клиент требует App Group `group.<bundle_id>`. ESign и профиль должны корректно выдать нужные entitlements и подписать вложенные бинарники; удаление расширений не отменяет требование App Group. Совместимость произвольного сертификата не подтверждена.

Перед выдачей артефакта проверяются bundle ID, название, ARM64, Mach-O platform и отсутствие шифрования исполняемого файла. Проверка артефакта не заменяет запуск на телефоне.

## Вариант для самостоятельной подписи и раздачи друзьям

`standalone-device` собирает тот же Telegram-клиент с MoonGram, отдельным постоянным bundle ID `app.moongram.ios.personal` и собственным контейнером Application Support. Эту IPA можно передавать друзьям: каждый входит в свой Telegram-аккаунт и использует подходящий для своего телефона способ подписи. API-реквизиты относятся к приложению; пользователям клиента создавать свои API-приложения не требуется.

В этом варианте отсутствуют системные расширения: Share, Widget, Siri Intents, Notification Service/Content, BroadcastUpload и Watch. Они остаются частью обычной сборки с подходящими профилями. App Groups entitlement в личном варианте не заявляется; PasscodeCore использует проверяемую собственную keychain group, сохраняя криптографию и проверки пароля. APNs и остальные права не появляются от одной переподписи.

Обычный режим хранит данные в App Group; личный — в отдельной базе. Переключать их под одним bundle ID автоматически запрещено конфигурацией. Политика выбирается явным build gate, а не ошибкой доступа к контейнеру. Изменение bundle ID или подписи уже установленного приложения может нарушить доступ к его локальным данным; обновления требуют сохранения identity и режима хранения. Контейнер официального Telegram не используется.

Для проверки старта есть `standalone-simulator`. Workflow запускает полный клиент на отдельном временном симуляторе, сохраняет запись запуска и снимок экрана, затем удаляет этот симулятор. Вход в аккаунт в CI не выполняется; такая проверка не подтверждает device keychain, ESign, push или авторизованные экраны.

## Обмен оформлением

```sh
node service/admin.mjs invite TELEGRAM_USER_ID
node service/src/main.mjs
```

Сервис слушает `127.0.0.1:8787`; для телефона нужен настроенный HTTPS reverse proxy. Выдавайте токен после проверки реального числового Telegram ID человека. Это ручная доверенная привязка приглашения, не автоматическое доказательство владения аккаунтом. После изменения приглашений перезапустите сервис.

Приложение публикует оформление отдельной кнопкой; балансы по умолчанию не публикуются. При открытии профиля настроенная синхронизация обновляет оформление друга с ограничением частоты. Офлайн сохраняется локальная копия. Снятие публикации не удаляет уже полученные другими людьми копии мгновенно.

## Эксперимент с исчезающим содержимым

Настройки выключены по умолчанию и ограничены одним указанным облачным личным чатом с согласившимся участником. Сохраняются ранее загруженные входящие текстовые снимки и полностью доступные байты открытых одноразовых фото/видео. Чатовые preview и синтетические варианты сообщений исключены. Секретные чаты, голосовые и кружки не включены в этот эксперимент.

Приложение не восстанавливает не полученное содержимое. При медленной сети копирование может проиграть удалению; событие удаления отмечает только уже существующий снимок либо ожидающую локальную запись. Само хранилище не меняет consumed/read/screenshot события и таймеры; отдельно включённый гостевой режим подавляет выбранные подтверждения прочтения. Хранилище отделено от экспорта и сервиса оформления; ключ ThisDeviceOnly не переносится на другой телефон.

Сохранение исчезающих копий и ghost mode ограничены [правилами API Telegram, пункт 1.4](https://core.telegram.org/api/terms). Эксперимент нельзя выдавать за обычную приватность Telegram или гарантировать отсутствие ограничений API. В исходники добавлен экспериментальный гостевой режим: отдельные выключенные по умолчанию переключатели прочтения облачных чатов/медиа, набора/записи, онлайна и просмотров историй. Они хранятся для каждого аккаунта только на устройстве и не зависят от визуалов. Обычные сообщения продолжают загружаться, локальные отметки прочтения и счётчики обновляются; подавленные операции синхронизации завершаются без отправки. Учтены темы/комментарии, ручное прочтение, медиа, упоминания и реакции. Секретные чаты сохраняют штатные подтверждения и таймеры; активность разговора в групповом звонке не скрывается. Уже отправленные события и другие сеансы не контролируются. После выключения очередное прочтение может подтвердить и более ранние сообщения. Полная компиляция и проверка между двумя аккаунтами пока не завершены.

## Прокси и дальнейшие функции

В официальной основе уже есть тип WEB и сетевой модуль WebProxyTransport. Его протокол предполагает совместимый доступный relay; прямой Telegram WSS `/apiws`, используемый `Flowseal/tg-ws-proxy`, требует отдельного адаптера. Гарантий работы во всех регионах или высокой скорости нет. Python-прокси, публичные пулы доменов и отключение TLS-проверок в приложение не встраивались.

Стрики отложены. Список проверок историй и разбор вариантов прокси находятся в локальных исследовательских документах; наличие функции у другого клиента не является результатом проверки MoonGram.

## Лицензия

Собственный код MoonGram предоставляется на условиях GPL-2.0-or-later. Основа Telegram и её зависимости сохраняют свои лицензии и уведомления. Проект не связан с Telegram FZ-LLC. Оригинальный логотип Telegram заменён собственным значком MoonGram для основного приложения.


## Публичная сборка без приватных API-ключей

Подготовлен отдельный workflow `public-template.yml`. Он использует нерабочие значения-заполнители, игнорирует переменные с настоящими API-ключами и не требует репозиторных секретов. Device-шаблон помечен `MoonGramRuntimeAPIRequired` и получает API-пару из ресурса приложения после локальной конфигурации. В шаблоне без этого ресурса нет рабочих API-реквизитов. Обычные приватные сборки используют прежний путь и не переключаются на этот режим автоматически.

`python3 tools/package_public_source.py` готовит `dist/MoonGram-public-source.zip` и проверяемый manifest. Архив содержит исходники и лицензию без Git-истории, приватных файлов и workflow приватной сборки. Публикация такого набора требует отдельного согласия владельца проекта.

После публичной device-сборки конфигурация добавляется на доверенном компьютере:

```sh
python3 tools/configure_ipa.py --template dist/MoonGram-template-personal.ipa --api .private/telegram.local.json --output dist/MoonGram-personal.ipa
```

Готовый настроенный IPA передаётся только доверенным людям: как и в обычном клиенте, API-пару можно извлечь из приложения. Конфигурация не содержит сеансов Telegram, кодов входа или сертификата подписи. После добавления ресурса IPA нужно подписать через ESign. Public simulator-шаблон использует только нерабочие заполнители и служит для проверки запуска до авторизации. Этот путь подготовлен и покрыт тестами упаковки; Objective-C интеграция и полная шаблонная сборка ещё не проверены на Mac.
